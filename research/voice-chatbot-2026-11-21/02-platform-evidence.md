# Stage 2: platform evidence and tool combinations

Checked 2026-11-21. These are documented options and design judgments, not a measured speed ranking. Exact account access and SDK compatibility remain untested. See [sources.md](sources.md) for the source register.

## Three architectures that must be compared fairly

| Family | Flow | Strong reason to choose it | Main question |
|---|---|---|---|
| Full-duplex voice frontend with separate reasoning | Continuous audio <-> voice model; asynchronous backend work | Keeps listening and speaking while an existing assistant works | Does it deliver useful results promptly, rather than merely filling silence? |
| Unified native audio | Audio <-> one speech/reasoning model, with tools | Removes application-managed STT/LLM/TTS handoffs | Do reasoning, voice, language and controls meet requirements? |
| Streaming cascade | Streaming STT -> streamed LLM clauses -> streaming TTS | Independent models, inspectable text, exact synthesis control | Can orchestration, endpointing and synthesis stay competitive? |

These are not mutually exclusive products. A managed API can expose one connection yet internally orchestrate multiple models. Bidirectional transport and barge-in do not alone establish a model's ability to understand simultaneous conversation.

Generic service-tier descriptions on the page must not be mistaken for model support: its table lists Standard only. Higher budget therefore does not establish a Sonic Priority tier. ## Model hosting, orchestration, and packaged platforms

| Layer | Candidates | What they solve; what they do not prove |
|---|---|---|
| Media and agent runtime | [LiveKit Agents](https://docs.livekit.io/agents/logic/sessions/), [Pipecat/Daily](https://docs.pipecat.ai/pipecat/learn/overview) | Transport, lifecycle, streaming, interruptions, plugins and metrics. Either can orchestrate native audio or a cascade. Adding an SFU/worker adds a media route; measure its total effect |
| Turn management | [LiveKit turn tuning](https://docs.livekit.io/agents/logic/turns/tuning/), [Pipecat Smart Turn](https://docs.pipecat.ai/api-reference/server/utilities/turn-detection/smart-turn-overview) | Improve timing and cancellation. Do not stack multiple endpoint timers without knowing which is authoritative |
| Fast text inference | [Groq](https://console.groq.com/docs/production-readiness/optimizing-latency), [Cerebras](https://inference-docs.cerebras.ai/capabilities/streaming), OpenAI/Google/AWS text models | Can accelerate the reasoning stage. Tokens/second is not time to first correct spoken clause; compare tool reliability and network route too |
| Packaged voice agents | [Vapi](https://docs.vapi.ai/quickstart/introduction), [Retell](https://docs.retellai.com/deploy/web-call), ElevenAgents, Deepgram Voice Agent | Fast integration, testing and operations; useful reference configurations. Product-level subsecond claims are not independently comparable |

Recommended cascade experiment: **LiveKit Agents (Node) + Deepgram Flux + a streamed text model + Cartesia Sonic 3.6**, with separate TTS trials using ElevenLabs and Sarvam. Pipecat/Daily is an equally credible comparison runtime if its turn/media integration proves better; adopting Python would introduce another runtime to the current TypeScript project. No need to run both frameworks in one audio path.

Google's modular alternative is **Cloud streaming STT -> streamed LLM -> Cloud bidirectional TTS**, including Chirp 3 HD. Check the exact TTS model/API combination: audio output streaming, incremental text input, and complete audio-file generation are different capabilities. [Google streaming synthesis](https://docs.cloud.google.com/text-to-speech/docs/create-audio-text-streaming), [Gemini-TTS API distinctions](https://docs.cloud.google.com/text-to-speech/docs/gemini-tts).

## On-device and self-hosted paths

| Option | What is established | Implication for this project |
|---|---|---|
| Android on-device recognition | Explicit availability check and on-device factory exist. [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer) | Test language/model availability; OS dictation is not evidence of arbitrary app-accessible continuous duplex speech |
| Gemini Nano/AICore | Current ML Kit device list for custom generation starts with supported newer Pixels; Pixel 8a is absent. [ML Kit GenAI](https://developers.google.com/ml-kit/genai) | Do not assume that a Pixel 8a can run the current public Nano custom agent API |
| LiteRT-LM, sherpa-onnx, whisper.cpp | Edge LLM framework; offline speech toolkit with Android support; local Whisper implementation. [LiteRT-LM](https://github.com/google-ai-edge/LiteRT-LM), [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | Credible local command/offline experiments. Benchmark model load, sustained real-time factor, memory, thermals and voice quality |
| Kyutai Moshi | Full-duplex streaming model/framework; published GPU latency is hardware-specific. [Official repository](https://github.com/kyutai-labs/moshi) | Self-hosted research reference; its ~200 ms L4 figure is not Pixel performance or a general factual-response guarantee |
| NVIDIA PersonaPlex; Qwen Omni | Public real-time speech-model repositories. [PersonaPlex](https://github.com/NVIDIA/personaplex), [Qwen3-Omni](https://github.com/QwenLM/Qwen3-Omni) | Self-hosted challengers, subject to model license, tools, hardware and sustained-load validation; not assumed phone-ready |
| Apple Foundation Models | Official framework exists; primary landing page required a JS/Markdown follow-up. [Apple docs](https://developer.apple.com/documentation/FoundationModels) | Outside current Android/web implementation; no Apple voice-stack capability or speed conclusion established in this study |

**Conclusion from evidence:** No ecosystem has established a measured universal lead here. The best starting architecture is a locally responsive audio client plus a native conversational voice layer, with slow application work separated. GPT-Live and Gemini Live deserve the first direct comparison; a strong streaming cascade and AWS/Azure/ElevenLabs references keep that recommendation falsifiable.
